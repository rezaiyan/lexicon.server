Cheat sheet: data keys the app understands

What the current app does when someone taps the push. Click Use to add the key to the data payload above. Without any of these, a tap just opens the app.

Deep links: key deep_link

ValueTap opens
vokab://reviewA review of the user's due cards
vokab://review/dueSame as above (any vokab://review/… works)
vokab://words/addThe add-words screen
vokab://insightsThe Insights screen
vokab://stats/weeklyThe Insights screen (any vokab://stats/…)
vokab://word/{wordId}A review of that one word. The id is the user's own word id, so only use it when sending to one user; a non-numeric id opens the Words tab

Any other link is ignored and the tap only opens the app. There are no links yet for Word Rush, Listening, the subscription screen or settings; those need an app update first.

Type: key type

ValueEffect
review_reminderTap opens the due-card review, ignoring any deep_link. On iOS it also gets the review-reminder notification style
streak_reminderiOS shows it with the streak-reminder notification style; the tap follows deep_link
announcementAny other value: no special handling, but it labels the push in your own data. A good choice for one-off messages

Blocked for manual sends: billing_issue (opens the subscription screen), subscription_updated (silent refetch) and account_deleted.

Set by the server: don't add these

notification_log_idAdded to every manual push so taps count as opens in History
categoryAdded by the message builder (system)
